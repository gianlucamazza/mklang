# Questions (operator only)

**Do not send this page to a reader.** The protocol does not define a
reader questionnaire. It tells you to show two materials, not explain, and
record the first question **they** ask.

The protocol's empty results register has four columns. The optional 24-hour
install note and the "do not explain" / "show them only" rules are the rest
of what a valid row needs. That is six questions. A seventh is the
after-five headline the protocol already names. There is no seventh
per-reader item in the protocol.

If you add a quiz so you can reach "5–7 questions," you have changed the
test.

## Per reader (1–6)

1. **Venue / person (role, not name)?**
   Protocol register column 2. Example shape: "colleague, ships agent
   products" — not a name.

2. **Did you show them only the repository README and the two demo
   recordings (`agent`, `language`)?**
   Protocol step 2. Yes / no. If no, the row is not a protocol row.

3. **Did you explain anything before their first question?**
   Protocol step 3: "Do not explain." Yes / no. If yes, the row is not a
   protocol row.

4. **What was the first question they asked?**
   Protocol step 3 and register column 3. Write it **verbatim**, in their
   words and their language.

5. **After README + demos only, did they understand what mklang is *for*?**
   Protocol register column 4 and the metric. Yes / no. You judge. The
   protocol does not define a rubric — do not invent one here.

6. **Did they install or try anything within 24 hours?**
   Protocol step 4 (optional) and register column 5. Yes / no / leave blank
   if you did not check.

## After five valid rows (7)

7. **Headline, then which branch?**
   Protocol headline: `_n/5 understood · n/5 tried · branch: —_`
   Then pick exactly one row from the protocol's metric table (≥3 do not
   understand / ≥3 understand but nobody tries / ≥3 understand and ≥1
   installs). If the counts match none of those three, write the counts and
   leave the branch blank — do not name a new branch.
